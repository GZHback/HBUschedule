# HBUschedule

河北大学课程表 Android App：在自己手机上登录教务系统，把课表变成能看的界面和桌面小组件。

不需要服务器，不需要注册账号，**课程数据只存在学生自己的设备里**。

## 为什么值得做

看课表要先过 WebVPN 登录，手机上体验很差，而且教务里的周次是「1-9周」这种相对说法，没法直接变成日历提醒。

本项目解决的是最后一步：**把课表搬到手机上**。登录链路全部在学生设备上完成，团队不持有任何人账号。

## 技术要点

- Kotlin + Jetpack Compose，`minSdk 26`（Android 8.0 起），`compileSdk 37`
- 零后端：WebView 登录网瑞达 WebVPN，CAS 统一认证、企业微信扫码、图形验证码都交给网页自己处理，App 不碰登录协议
- 登录后不再依赖页面 JS：从 WebView 取到会话 cookie，用 OkHttp 按「代理前缀 → 课表页 → callback」纯 HTTP 直取青果 URP 接口，失败时回落到 WebView 手动操作
- 学号/密码/验证码在 App 自己的输入框里打，点「填入页面」一次注入（等价于粘贴）：登录页逐键输入时会重写输入框内容，光标被甩回最左边，打 `2025` 出来是 `5202`，而粘贴不受影响
- 命令行脚本走的是另一条路：`v.hbu.cn` 的 `auth_type=local` 学号密码登录（撞上图形验证码时把图片存下来人工读），只用于验证接口，不打包进 App
- 周次以接口返回的 `timeAndPlaceList[].classWeek` **24 位 0/1 位图**为准，不解析中文周次文案
- 「今天第几周」不是数出来的：拿设备日期减去第 1 周周一算，所以它不会自己漂一周或多一周；会出错的只有那个起点，因此起点做成界面可改的设置（默认 2026-08-31，按教务页面「第 5 周 星期一」核对过），抓取时还会试着从课表页 HTML 读教务自己标的本周周次，读到了又和算出来的不一致就在课表上提示，由学生点一下校准（不自动覆盖）。教务接口里没有节假日与调休，周次对上不等于今天一定上课
- 教务只给名字、没有 `timeAndPlaceList` 的课（实验、课程设计）可以在课表下面点「排课」自己补星期/节次/周次/地点，也能完全自建一门课；手动记录存本机，重新抓课表不会覆盖，`.ics` 导出同样带上它们
- 界面照 iOS 那套来：浅灰页面底 + 圆角白卡片 + 0.6dp 内缩分隔线 + 固定字号层级，数全在 `ui/Design.kt` 一处，界面只引用名字；顶部是 iOS 分段控件（白块滑动），两页之间 `Crossfade`
- 课程色是 iOS 色相压到饱和度 0.56、亮度按「白字对比 4.65:1」反推出来的，所以十种颜色深浅一致，白字都读得住
- 格子里只放课名（最多两行）和教室，老师名字挪到点开才看：列宽只有几十 dp，多一行字课名就被断成碎纸
- 删除手动记录一定先问一句（说清楚只删本机这条、教务里的课不动），删了不会自己回来
- 状态栏底色跟页面同色并强制深色图标，浅灰底上原本白色的时间完全看不见；状态栏高度只在最外层扣一次，之前两层各扣一次，顶部多出一条空白
- 顶部是「今天 / 课表」两个标签，打开默认停在「今天」这一页，只列当天那几节并标出哪节还没上；它和周课表读的是同一个 `Schedule`，所以手动排的课一并出现在上面。「已结束 / 正在上 / 还没上」的判断放在不碰界面的 `TodayAgenda` 里，能直接喂假时间点单测；这一页只在打开时算一次，不会自己走到下一节
- 节次共 11 节：上午 1-4、下午 5-8、晚上 9-11，第 1 节 08:20-09:05
- `.ics` 导出把周次拆成步长 1 或 2 的连续段，一段一条 `RRULE`，双周课 `INTERVAL=2`

## 目录结构

```
app/                    Android 应用（Kotlin + Compose）
  src/main/java/cn/hbu/schedule/
    data/               接口 JSON → 课表模型、手动排课本机存储、学期起点与周次校准
    model/              课表模型、节次作息、学期周次换算
    export/             .ics 日历导出
    network/            登录态下的课表直取（OkHttp + WebVPN 代理前缀）
    ui/                 登录 WebView、周课表与「今天」两页、课程详情、排课与学期设置表单
  src/test/             单元测试，测试数据用 docs 下的真实样例
docs/
  sample_raw_schedule.json   真实教务响应（已脱敏），单元测试夹具
tools/
  capture-schedule.mjs       零依赖命令行抓取脚本，用于验证接口
.github/workflows/           CI：跑测试并产出 debug APK
kbzq.py                 最早的 Playwright 抓取脚本（项目起点）
```

## 构建

CI 会自动构建：推送后在仓库的 **Actions** 页面找到最近一次成功的 run，页面底部 Artifacts 里下载 `hbu-schedule-debug`（需要登录 GitHub，产物保留 90 天）。

本地构建需要 Gradle 和 Android SDK（仓库里不放 `gradle-wrapper.jar`）：

```bash
gradle :app:test          # 跑单元测试
gradle :app:assembleDebug # 产出 app/build/outputs/apk/debug/app-debug.apk
```

装到手机：把 apk 传到手机打开安装，会提示「未知来源」，属正常现象（debug 签名）。

## 抓取脚本

想验证接口是否还能用，不需要装任何依赖：

```bash
node tools/capture-schedule.mjs --probe   # 只测连通性和登录页
node tools/capture-schedule.mjs           # 学号密码登录，导出 schedule_raw.json
```

输出文件（默认 `schedule_raw.json`，`--meta` 导出的 `schedule_term.json`）含真实个人课表，由 `.gitignore` 里的 `schedule_*.json` 一条挡住——去掉这条规则，这些文件就会重新变成可提交状态。不要提交、不要外传。
